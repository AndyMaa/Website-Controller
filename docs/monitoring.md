# 消息是怎样识别的

## 自动发现与备用规则

发现范围是你正常访问网站时产生的数据。XHR / Fetch 的 JSON 响应在网站读取完成后进行分析；推送按接收到的文本事件识别。只有满足严格条件的同源未读计数 GET 才会加速轮询。带令牌或签名查询参数、写入动作、POST 等请求继续被动监听。

二进制或加密推送、不认识的字段结构、部分独立 iframe 和特殊认证可能需要页面规则补充。软件提供“正在发现”“页面守候”“等待登录验证”等具体状态，便于继续配置。

“页面已连接”表示加载与心跳正常；“已发现消息接口”表示观察到可识别数据。光厂、站酷需要在你登录后打开实际消息页，才能确认其当前来源。自动发现需要登录后的实际流量，公开首页的加载结果不能证明账号内消息已接通。

多个可识别未读来源以最大值展示，独立来源的增量也会触发提醒；该数字不是跨频道精确总和。`—` 表示数量尚未知。消息正文仅从明确的新消息推送或用户选定区域记录摘要。

电脑睡眠、断网、完全退出、账号过期期间无法保证实时提醒。实际到达速度也受原网站的更新机制和网络影响。Windows 勿扰设置可能抑制桌面通知。
